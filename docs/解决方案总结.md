# 解决需要登录网站克隆问题 - 方案总结

## 📋 问题描述

原工具在克隆需要登录的网站时存在限制：
- 无法访问需要登录才能查看的页面
- 无法克隆私有内容
- 无法处理需要认证的资源

## ✅ 解决方案

我们实现了三种解决方案，覆盖不同的使用场景：

### 方案 1：Cookie 认证（推荐）⭐⭐⭐⭐⭐

**原理**：在浏览器启动后，通过 Puppeteer 的 `page.setCookie()` 方法设置 Cookie。

**优点**：
- ✅ 快速、简单
- ✅ 不需要关闭浏览器
- ✅ 可以自动化
- ✅ 适用于大多数网站

**缺点**：
- ❌ Cookie 会过期，需要定期更新
- ❌ 需要手动导出 Cookie

**实现代码**：
```typescript
// 设置 Cookies
if (cookies.length > 0) {
  await page.setCookie(...cookies);
}
```

**使用示例**：
```
请克隆 https://example.com/dashboard，使用 cookies：
[
  {
    "name": "session_id",
    "value": "abc123",
    "domain": ".example.com"
  }
]
```

**适用场景**：
- GitHub 私有仓库
- 一般的后台管理系统
- 会员专属页面
- 需要简单认证的网站

---

### 方案 2：用户数据目录（User Data Directory）⭐⭐⭐⭐

**原理**：使用已有浏览器的用户数据目录启动 Puppeteer，继承所有登录状态。

**优点**：
- ✅ 保持完整登录状态
- ✅ 支持所有认证方式
- ✅ 不需要导出 Cookie
- ✅ 支持复杂认证流程

**缺点**：
- ❌ 需要关闭浏览器
- ❌ 可能有安全风险（共享浏览器数据）

**实现代码**：
```typescript
const launchOptions: any = {
  headless: headless,
  args: ["--no-sandbox", "--disable-setuid-sandbox"],
};

if (userDataDir) {
  launchOptions.userDataDir = userDataDir;
}

browser = await puppeteer.launch(launchOptions);
```

**使用示例**：
```
请克隆 https://example.com/dashboard，使用用户数据目录：
C:\Users\YourUsername\AppData\Local\Google\Chrome\User Data
```

**适用场景**：
- 企业内网系统
- 复杂的 SSO 认证
- 需要证书认证的网站
- 频繁克隆同一网站

---

### 方案 3：非无头模式 + 手动登录⭐⭐⭐

**原理**：启动可见的浏览器窗口，用户手动登录后，工具自动克隆页面。

**优点**：
- ✅ 支持任何登录方式
- ✅ 可以处理验证码
- ✅ 可以处理双因素认证
- ✅ 无需导出任何凭证

**缺点**：
- ❌ 需要手动操作
- ❌ 无法自动化
- ❌ 需要更长的等待时间

**实现代码**：
```typescript
browser = await puppeteer.launch({
  headless: false,  // 显示浏览器窗口
  args: ["--no-sandbox", "--disable-setuid-sandbox"],
});
```

**使用示例**：
```
请克隆 https://example.com/login，使用非无头模式，等待 60000 毫秒
```

**适用场景**：
- 需要输入验证码的网站
- 双因素认证（2FA）
- 复杂的登录流程
- 调试和测试

## 🔧 技术实现细节

### 1. 参数扩展

在工具的 `inputSchema` 中添加了三个新参数：

```typescript
cookies: {
  type: "array",
  description: "要设置的 Cookie 数组",
  items: {
    type: "object",
    properties: {
      name: { type: "string" },
      value: { type: "string" },
      domain: { type: "string" },
      // ... 其他可选属性
    },
  },
},
userDataDir: {
  type: "string",
  description: "浏览器用户数据目录路径",
},
headless: {
  type: "boolean",
  description: "是否使用无头模式",
  default: true,
}
```

### 2. Cookie 设置逻辑

```typescript
// 解析参数
const cookies = (args?.cookies as any[]) || [];
const userDataDir = (args?.userDataDir as string) || "";
const headless = (args?.headless as boolean) ?? true;

// 启动浏览器（支持用户数据目录）
const launchOptions: any = {
  headless: headless,
  args: ["--no-sandbox", "--disable-setuid-sandbox"],
};

if (userDataDir) {
  launchOptions.userDataDir = userDataDir;
}

browser = await puppeteer.launch(launchOptions);
const page = await browser.newPage();

// 设置 Cookies
if (cookies.length > 0) {
  await page.setCookie(...cookies);
}

// 访问页面
await page.goto(url, { waitUntil: "networkidle0" });
```

### 3. 状态消息输出

```typescript
if (cookies.length > 0) {
  statusMessage += `使用 Cookie 数量: ${cookies.length}\n`;
}
if (userDataDir) {
  statusMessage += `使用用户数据目录: ${userDataDir}\n`;
}
statusMessage += `无头模式: ${headless ? '是' : '否'}\n`;
```

### 选择决策树

```
需要克隆登录网站？
├─ 是否有验证码/2FA？

```

### 推荐使用场景

1. **一般情况**：使用 Cookie 方式（方案1）
   - 最平衡的解决方案
   - 适用于 80% 的场景

2. **企业内网**：使用用户数据目录（方案2）
   - 复杂的 SSO 认证
   - 需要证书认证

3. **有验证码**：使用非无头模式（方案3）

   - 双因素认证

## 🔒 安全考虑

### Cookie 安全

1. **不要分享**：Cookie 包含登录凭证
2. **定期更新**：Cookie 会过期
3. **本地存储**：不要上传到云端
4. **使用后删除**：及时清理 Cookie 记录

### 用户数据目录安全

1. **关闭浏览器**：使用前必须关闭
2. **只读访问**：工具不会修改数据
3. **注意权限**：确保有读取权限
4. **备份数据**：使用前建议备份

### 非无头模式安全

1. **可见操作**：所有操作都可见
2. **手动控制**：用户完全控制登录过程
3. **无凭证泄露**：不需要导出任何凭证
