# 如何克隆需要登录的网站

本指南介绍如何使用网页克隆工具克隆需要登录的网站。

## 🔐 问题说明

默认情况下，Puppeteer 启动的浏览器是一个全新的会话，没有任何登录状态。因此无法访问需要登录才能查看的页面。

## ✅ 解决方案

我们提供了三种解决方案：

### 方案 1：使用 Cookie（推荐）

适用于：你已经在浏览器中登录过，可以导出 Cookie。

#### 步骤 1：获取 Cookie

**方法 A：使用浏览器开发者工具**

1. 在浏览器中登录目标网站
2. 按 `F12` 打开开发者工具
3. 切换到 `Application` 或 `存储` 标签
4. 找到 `Cookies` 部分
5. 复制需要的 Cookie（通常是 `session`、`token`、`auth` 等）

**方法 B：使用浏览器扩展**

安装 Cookie 导出扩展（如 EditThisCookie、Cookie-Editor）：
1. 登录目标网站
2. 点击扩展图标
3. 导出 Cookie（JSON 格式）

#### 步骤 2：使用 Cookie 克隆

```typescript
// 示例：克隆需要登录的页面
请使用 clone_webpage 工具克隆 https://example.com/dashboard，使用以下 cookies：
[
  {
    "name": "session_id",
    "value": "abc123xyz789",
    "domain": ".example.com"
  },
  {
    "name": "auth_token",
    "value": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "domain": ".example.com"
  }
]
```

**Cookie 参数说明：**

| 参数 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | Cookie 名称 |
| `value` | ✅ | Cookie 值 |
| `domain` | ❌ | Cookie 域名（建议填写，格式：`.example.com`） |
| `path` | ❌ | Cookie 路径（默认 `/`） |
| `expires` | ❌ | 过期时间戳（秒） |
| `httpOnly` | ❌ | 是否 HttpOnly |
| `secure` | ❌ | 是否 Secure（HTTPS） |
| `sameSite` | ❌ | SameSite 属性（`Strict`、`Lax`、`None`） |

### 方案 2：使用浏览器用户数据目录

适用于：你想使用已有浏览器的登录状态（Chrome、Edge 等）。

#### 步骤 1：找到用户数据目录

**Windows (Chrome):**
```
C:\Users\你的用户名\AppData\Local\Google\Chrome\User Data
```

**Windows (Edge):**
```
C:\Users\你的用户名\AppData\Local\Microsoft\Edge\User Data
```

**macOS (Chrome):**
```
~/Library/Application Support/Google/Chrome
```

**Linux (Chrome):**
```
~/.config/google-chrome
```

#### 步骤 2：使用用户数据目录克隆

```typescript
// 示例：使用 Chrome 的登录状态
请克隆 https://example.com/dashboard，使用用户数据目录：
C:\Users\jiangjj\AppData\Local\Google\Chrome\User Data
```

**⚠️ 注意事项：**

1. **关闭浏览器**：使用用户数据目录前，必须先关闭对应的浏览器（Chrome/Edge）
2. **数据安全**：工具只读取登录状态，不会修改你的浏览器数据
3. **Profile 目录**：如果使用多个 Profile，需要指定具体的 Profile 目录（如 `Default`、`Profile 1`）

### 方案 3：交互式登录（手动登录）

适用于：需要手动输入验证码、双因素认证等。

#### 使用非无头模式

```typescript
// 示例：打开浏览器窗口，手动登录
请克隆 https://example.com/dashboard，使用非无头模式（headless: false），等待 30000 毫秒
```

**操作步骤：**

1. 工具会打开一个真实的浏览器窗口
2. 你可以在窗口中手动登录
3. 登录完成后，等待指定时间（如 30 秒）
4. 工具会自动克隆当前页面

**参数设置：**
- `headless: false` - 显示浏览器窗口
- `waitTime: 30000` - 等待 30 秒（给你时间登录）

## 📝 完整示例

### 示例 1：使用 Cookie 克隆 GitHub 私有仓库

```json
{
  "url": "https://github.com/your-private-repo",
  "cookies": [
    {
      "name": "user_session",
      "value": "your_session_token_here",
      "domain": ".github.com",
      "path": "/",
      "secure": true,
      "httpOnly": true
    }
  ],
  "outputDir": "D:\\github-clone",
  "waitTime": 5000
}
```

### 示例 2：使用用户数据目录克隆企业内网

```json
{
  "url": "https://intranet.company.com/dashboard",
  "userDataDir": "C:\\Users\\jiangjj\\AppData\\Local\\Google\\Chrome\\User Data",
  "outputDir": "D:\\intranet-clone",
  "waitTime": 5000
}
```

### 示例 3：手动登录后克隆

```json
{
  "url": "https://example.com/login",
  "headless": false,
  "waitTime": 60000,
  "outputDir": "D:\\example-clone"
}
```

**操作流程：**
1. 浏览器窗口打开
2. 在 60 秒内手动登录
3. 登录成功后，等待页面加载
4. 工具自动克隆页面

## 🔧 故障排除

### 问题 1：Cookie 设置后仍然未登录

**可能原因：**
- Cookie 已过期
- Cookie 的 `domain` 设置不正确
- 缺少必要的 Cookie

**解决方案：**
1. 重新获取 Cookie（确保是最新的）
2. 检查 `domain` 是否正确（通常需要加 `.` 前缀，如 `.example.com`）
3. 导出所有 Cookie，不要只导出部分

### 问题 2：用户数据目录无法使用

**可能原因：**
- 浏览器未关闭
- 路径不正确
- 权限问题

**解决方案：**
1. 完全关闭浏览器（包括后台进程）
2. 检查路径是否正确（Windows 使用 `\\` 或 `/`）
3. 确保有读取权限

### 问题 3：非无头模式下浏览器自动关闭

**可能原因：**
- `waitTime` 设置太短

**解决方案：**
- 增加 `waitTime`（如 60000 毫秒 = 60 秒）
- 给自己足够的时间完成登录

## 💡 最佳实践

### 1. Cookie 方式（推荐）

**优点：**
- ✅ 快速、简单
- ✅ 不需要关闭浏览器
- ✅ 可以自动化

**缺点：**
- ❌ Cookie 会过期
- ❌ 需要手动导出

**适用场景：**
- 一次性克隆
- 自动化脚本
- Cookie 有效期长的网站

### 2. 用户数据目录方式

**优点：**
- ✅ 保持完整登录状态
- ✅ 支持所有认证方式
- ✅ 不需要导出 Cookie

**缺点：**
- ❌ 需要关闭浏览器
- ❌ 可能有安全风险

**适用场景：**
- 频繁克隆同一网站
- 复杂的认证流程
- 企业内网

### 3. 非无头模式（手动登录）

**优点：**
- ✅ 支持任何登录方式
- ✅ 可以处理验证码
- ✅ 可以处理双因素认证

**缺点：**
- ❌ 需要手动操作
- ❌ 无法自动化

**适用场景：**
- 有验证码的网站
- 双因素认证
- 复杂的登录流程

## 🔒 安全建议

1. **不要分享 Cookie**：Cookie 包含你的登录凭证，不要分享给他人
2. **定期更新 Cookie**：Cookie 会过期，需要定期重新获取
3. **使用临时 Cookie**：如果可能，使用临时会话的 Cookie
4. **注意权限**：确保克隆的内容你有权访问
5. **遵守法律**：不要克隆未经授权的内容

## 📚 技术原理

### Cookie 工作原理

```typescript
// Puppeteer 设置 Cookie
await page.setCookie({
  name: 'session_id',
  value: 'abc123',
  domain: '.example.com',
  path: '/',
  expires: Date.now() / 1000 + 3600, // 1 小时后过期
  httpOnly: true,
  secure: true,
  sameSite: 'Lax'
});
```

### 用户数据目录工作原理

```typescript
// Puppeteer 使用用户数据目录
const browser = await puppeteer.launch({
  userDataDir: 'C:\\Users\\xxx\\AppData\\Local\\Google\\Chrome\\User Data',
  headless: true
});
```

这样启动的浏览器会使用指定目录中的所有数据，包括：
- Cookies
- 本地存储
- 缓存
- 扩展
- 登录状态
